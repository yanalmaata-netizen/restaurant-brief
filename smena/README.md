# Передача смены

Веб-приложение для передачи смены между менеджерами ресторана fine dining.
Один менеджер заполняет смену по блокам, второй **подтверждает каждый блок** —
пока не подтвердил, смена не закрыта.

Адрес после деплоя: `<проект>.pages.dev/smena/`

## Откуда взята логика

| Практика | Что взято |
|---|---|
| Manager's Red Book (США) и его цифровые версии (7shifts, ShiftNote, Xenia) | блоки суточного журнала, архив с поиском |
| Отельный MOD pass-on log | отдельные блоки под банкеты и под обещания гостям |
| HSE после Piper Alpha | передача письменная **и** подтверждаемая, а не «оставил записку» |
| Медицинский протокол I-PASS | подтверждение приёма по каждому блоку (read-back) |
| Daily line-up в Ritz-Carlton | блок брифинга: коротко, до 15 минут, каждый день |
| Jolt, Zenput, Trail | KPI: процент выполнения, скорость закрытия, что осталось незакрытым |

## Что внутри

- **13 блоков передачи:** брифинг, готовность зала, журнал смены, гости вечера,
  резервы и банкеты, кухня, бар и вино, закупка и склад, техника и здание, персонал,
  касса, итоги, закрытие и безопасность.
- **Готовность зала** — проход по залу до первого гостя: полировка приборов, скатерти,
  свет и свечи, музыка, температура, цветы, туалеты, план посадки. Десять пунктов,
  из которых считается показатель «готовность зала до открытия».
- **Бар и вино отдельным блоком.** Открытые бутылки по бокалам с остатком и сроком,
  что декантировать к завтрашним броням, температура винного шкафа, бой и списания.
- **Аллергии и диеты** — отдельный вид записи в гостях и отдельное поле в каждой броне.
  Число отмеченных аллергий выведено в отчёт.
- **Брифинг перед сменой.** Проведён или нет, кто был, акцент дня, о чём говорили.
  Доля смен с брифингом попадает в отчёт — видно, соблюдается ли ритуал.
- **Журнал смены.** Записи по ходу вечера, каждая со временем и автором, новые сверху.
  Заполняется не в конце смены, а тогда, когда что-то случилось.
- **Надиктовка голосом.** Кнопка микрофона у каждого текстового поля: говорите — появляется текст.
  Работает в Chrome и в Safari с iOS 14.5. **Аудио никуда не сохраняется**, в смену попадает
  только распознанный текст. Если браузер не умеет распознавать речь, кнопка просто не показывается.
- **Комментарии к задачам.** Под каждой задачей своя переписка: кто что сделал, почему стоит.
  История остаётся, даже когда задача переходит из смены в смену.
- **Блокирующие подтверждения.** Смену нельзя передать без выручки, наличных в кассе
  и галочек по стоп-листу, банкетам на завтра и пересчёту кассы.
- **Переходящие задачи.** Незакрытая задача переносится в следующую смену и считает,
  сколько смен она висит. С трёх смен подсвечивается красным на главной.
- **Приём по блокам.** Принимающий жмёт «Принял» на каждом блоке; кнопка приёма смены
  разблокируется только после всех девяти.
- **Фото** (до 4 на блок) в блоках «Гости», «Кухня», «Техника», «Закрытие» —
  сжимаются до 1000 px прямо в браузере.
- **Архив с поиском** по всему содержимому смен и печать/PDF принятой смены.
- **Отчёт с KPI** за 7 дней, 30 дней или всё время + выгрузка в таблицу.

## Отчёт и KPI

Вкладка «Отчёт» считает по принятым сменам за период:

| Показатель | Как считается | Норма |
|---|---|---|
| **Стандарт** | | |
| Готовность зала до открытия | доля отмеченных пунктов в блоке «Готовность зала» | 100% |
| Брифинг проведён | доля смен с отметкой о брифинге | 100% |
| Чек-лист закрытия | доля отмеченных пунктов в блоке закрытия | 100% |
| Полнота передачи | доля блоков, в которых хоть что-то заполнено | от 80% |
| **Гости** | | |
| Обещаний не закрыто | записи «Обещание гостю» со статусом «Открыто» | ноль |
| Аллергий и диет отмечено | записи в гостях плюс заполненное поле в бронях | сколько есть |
| Жалоб, гостей за период | | |
| **Риски** | | |
| No-show и отмены в день брони | из блока «Резервы и банкеты» | |
| Банкетов без предоплаты или меню | предоплата «Нет» либо меню «Не согласовано» | ноль |
| Смен с неполной готовностью зала | готовность зала меньше 100% | ноль |
| **Задачи и скорость** | | |
| Закрыто / поставлено, открыто, висят 3+ смены | | ноль зависших |
| От передачи до приёма | минуты между «Передать» и «Принять» | чем меньше |

Ниже — таблица по сменам на 20 колонок и три способа её забрать:
**«Скопировать таблицу»** (вставляется в Google Таблицу как есть),
**«Скачать CSV»** и автовыгрузка при каждом приёме смены.

## Автовыгрузка в Google Таблицу

Создайте таблицу, в ней Расширения → Apps Script, вставьте код:

```javascript
function doPost(e) {
  var data = JSON.parse(e.postData.contents);
  var ss = SpreadsheetApp.getActive();
  var sh = ss.getSheetByName('Смены') || ss.insertSheet('Смены');
  var rows = data.rows || [];
  if (sh.getLastRow() === 0 && rows.length) sh.appendRow(rows[0]);  // шапка один раз
  for (var i = 1; i < rows.length; i++) sh.appendRow(rows[i]);
  return ContentService.createTextOutput('ok');
}
```

Развернуть → Новое развёртывание → Веб-приложение, доступ «Все».
Полученную ссылку вставьте в приложении на вкладке «Отчёт».
Дальше строка уходит в таблицу сама при каждом приёме смены.

Приложение отправляет запрос без чтения ответа (`mode: 'no-cors'`) — браузер не пустит
его читать чужой домен. Поэтому «отправлено» означает «ушло», а не «записалось».
Первый раз проверьте таблицу глазами.

## Файлы

```
smena/index.html          приложение целиком (вёрстка, логика, стартовая схема блоков)
functions/api/smena.js    ручка /api/smena — чтение и запись в KV
_headers                  no-store для /api/* и /smena/*
```

## Данные хранятся в двух местах

```
KV на сервере   ← побеждает всегда, общий для всех телефонов
localStorage    ← показывается мгновенно при открытии, работает без сети
```

Если KV не привязан, приложение молча работает в локальном режиме — в шапке
пишет «Только этот телефон». Это рабочий режим для одного устройства,
но два менеджера с разных телефонов друг друга не увидят.

Защита от затирания: у состояния есть `rev`. Если второй менеджер сохранил
раньше, сервер отвечает **409**, и приложение спрашивает, перезаписать или
подтянуть свежую версию. Проверку не убирать — смену ведут два человека одновременно.

## Развернуть

Делает Yan (это панели в браузере, у Claude нет прав):

1. Cloudflare Pages → проект из репозитория `yanalmaata-netizen/restaurant-brief`,
   ветка с приложением. Framework preset: **None**, build command и output directory — **пустые**.
2. Workers & Pages → KV → создать namespace, например `smena-state`.
3. Настройки Pages-проекта → Settings → Bindings → KV namespace,
   имя переменной строго **`SMENA_KV`**.
4. Пересобрать деплой, чтобы привязка подхватилась.

Проверка после деплоя:

```bash
curl -s -o /dev/null -w "%{http_code}\n" https://<проект>.pages.dev/smena/
curl -s https://<проект>.pages.dev/api/smena
```

Первая команда должна вернуть `200`, вторая — JSON вида `{"rev":0,"state":null,"at":0}`.
Если вторая отдаёт 503 — привязка `SMENA_KV` не сделана или не пересобран деплой.

## Как менять блоки и поля

Вся схема передачи — в массиве `BLOCKS` в начале скрипта в `index.html`.
Блок описывается так:

```javascript
{id:'kitchen', ic:'🍳', ph:1, t:'Кухня и бар',
 confirm:'Стоп-лист передан и актуален',      // блокирующая галочка
 hint:'подсказка курсивом',                   // необязательно
 fields:[{k:'stop', ty:'area', l:'Стоп-лист'}],   // поля блока
 item:[{k:'what', ty:'txt', l:'Что'}]}            // повторяющиеся позиции
```

Типы полей `ty`: `txt`, `num`, `area`, `date`, `chk`, `sel` (со списком в `o`).
`req:1` у поля делает его обязательным для передачи смены. `ph:1` у блока включает фото.

При правке файла поднимайте версию в `var VER='1.0'` — по ней видно,
обновилась ли страница у менеджеров.
